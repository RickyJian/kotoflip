# Plan Writer

在動手寫程式碼之前，先把「討論結果」落地成文件，確保實作方向有共識、有紀錄可追溯。

## 適用範圍

僅適用於 `.agents/docs/SPECS.md` 中列出的**功能性 spec 工作**。不確定某項工作是否屬於此範圍時，**先詢問開發人員**，不可自行判斷。

## 資料夾結構

```
.agents/docs/<topic-slug>/
  plan.md
  decision.md
  progress_1.md
  progress_2.md
  ...
```

`<topic-slug>` 由開發人員明確告知，不可自行猜測或自動命名。

## 建立新 topic 資料夾的時機

1. 開發人員明確要求新增時
2. 準備異動程式碼前，若該功能尚無對應資料夾

## 實作前流程

1. 開發人員需明確指出主題名稱／資料夾
2. 找到對應的 `progress_N.md`，並讀取該檔案 + `plan.md` + `decision.md`
3. 若找不到資料夾／檔案，或內容不足以支撐實作判斷（spec 不完整）→ **停下詢問開發人員**，不可自行猜測補完，待資訊補齊才能繼續

## 三份檔案格式

### plan.md（覆寫最新狀態）

```markdown
# Plan: <主題名稱>

## 背景介紹
<這個 spec 的情境、前提、為什麼需要這個功能/改動>

## 目標
<這個功能/改動要達成什麼>

## 現況

### 待執行
- [ ] <任務項目 1>（[progress_1.md](progress_1.md)）

### 已完成
- [x] <任務項目 0>（[progress_1.md](progress_1.md)）

## 總結
<目前整體執行結果摘要：哪些完成、哪些還需要調整>

### 影響範圍
<此次調整/實作會影響到哪些項目、檔案、既有功能>
```

一個 checkbox 對應一份 `progress_N.md` 檔案；該檔案內所有主項目都完成，checkbox 才移到「已完成」。過程中若衍生新任務，補回「待執行」。

### decision.md（單一檔案，累加記錄，不覆寫）

```markdown
# DECISION

## <討論項目/決策標題>

**討論**：<討論了什麼問題/背景>
**選項**：
- A. <選項A> — <優缺點>
- B. <選項B> — <優缺點>
**決定**：採用 <A/B>
**理由**：<為什麼>
**被否決的原因**（若適用）：<為什麼不選其他選項>
**時間**：2026-01-01
```

單一方案、無比較對象時，省略「選項」段落。新決策依序接在檔案最下面。

### progress_N.md（相似項目歸入同檔）

```markdown
# <這份檔案裡相關項目的統稱>

> 對應 [plan.md](plan.md) 「待執行」項目：<任務項目名稱>

執行前需參閱 `decision.md` 檔案才可開始執行。

## <主項目 1 標題>

<執行方式說明：具體要怎麼做、牽涉到哪些檔案/模組、注意事項>

- [ ] <子項目 1-1>
- [ ] <子項目 1-2>

## <主項目 2 標題>

<執行方式說明>

- [ ] <子項目 2-1>

## 總結

<目前執行到的結果或完成後的資訊，僅記錄當下狀況，會隨進度覆寫更新>
```

## 實作中流程

1. 依 `progress_N.md` 裡的主項目**逐一**執行，不可跳著做或一次做多個
2. **每完成一個主項目**（含底下所有子項目 checkbox 都勾完）→ **停下來交給開發人員審閱確認**，確認通過才能開始下一個主項目

## 完成後流程（每個主項目確認通過後）

1. 勾起該主項目及子項目的 checkbox（`progress_N.md`）
2. 若 `progress_N.md` 裡的主項目**全部**完成 → 回到 `plan.md`，將對應的 checkbox 從「待執行」移到「已完成」
3. 過程中若有新決策／討論 → 累加寫入 `decision.md`
4. 更新 `plan.md` 的「總結」與 `progress_N.md` 的「總結」，反映當下狀態
5. 若過程中衍生新任務 → 補回 `plan.md` 的「待執行」，連結指向對應的 `progress_N.md`
